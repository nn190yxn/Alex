# 我赢AI 网页端实施清单 v1

## 1. 范围冻结（本版）
- 目标：先完成 Phase 0 + Phase 1，形成可上线、可注册、可付费、可使用的 MVP。
- 范围内：平台底座 + 免费层 10 个工具 + 会员与限额 + 基础运营后台。
- 范围外：进阶层 8 个工具、高阶层 11 个工具（进入后续迭代）。

## 2. 里程碑与节奏
- M0（第 1 周）：技术底座完成，账号/权限/支付闭环打通。
- M1（第 2-3 周）：免费工具 1-5 上线（文案类 + 计算类）。
- M2（第 4-5 周）：免费工具 6-10 上线（排班与内容类）。
- M3（第 6 周）：联调、压测、灰度、正式发布。

## 3. 工作流规范
- 分支策略：`main` 仅接收经过评审的合并，开发在特性分支进行。
- 发布策略：每周至少一次可部署版本，禁止长周期大分支。
- 文档策略：每轮开发同步更新 `工程开发进度.md` 与本清单状态。
- 缺陷策略：P0 当日修复，P1 48 小时内修复，P2 纳入迭代。

## 4. Phase 0（第 1 周）平台底座任务

### 4.1 工程与环境
- [ ] 初始化前后端项目骨架（前端 Vue3 + Vite，后端 Node.js + Express）。
- [ ] 配置环境变量模板（`env.example`）：`OPENAI_API_KEY`、`MYSQL_DSN`、`REDIS_URL`、`WECHAT_PAY_*`。
- [ ] 配置日志体系（请求日志、错误日志、审计日志）。
- [ ] 配置基础监控（健康检查、接口耗时、错误率）。

### 4.2 账号与鉴权
- [ ] 用户注册（手机号或邮箱 + 验证码）。
- [ ] 用户登录（JWT + Refresh Token）。
- [ ] 用户资料接口（昵称、行业、门店类型、城市）。
- [ ] 登录态中间件与权限守卫。

### 4.3 会员与计费
- [ ] 会员等级模型：free/starter/pro/annual-pro。
- [ ] 功能权限矩阵模型：按功能编码绑定可用等级。
- [ ] 次数配额模型：按用户+功能+日期计数。
- [ ] 微信支付下单、回调验签、订单幂等更新。
- [ ] 订阅到期任务（定时降级）。

### 4.4 数据层
- [ ] 建库建表：users、plans、subscriptions、orders、tool_usage、tool_results、audit_logs。
- [ ] Redis 键设计：配额计数、限流锁、短期缓存。
- [ ] 统一 DAO/Repository 层，避免业务直接写 SQL。

### 4.5 运营后台（最小可用）
- [ ] 用户列表与会员状态查询。
- [ ] 订单列表与支付状态查询。
- [ ] 功能调用量面板（按功能/按日）。
- [ ] 错误告警列表（5xx、超时、API失败）。

## 6. API 清单（MVP）
- [ ] `POST /api/auth/register` 用户注册。
- [ ] `POST /api/auth/login` 用户登录。
- [ ] `GET /api/user/profile` 用户信息。
- [ ] `GET /api/membership/current` 当前会员状态。
- [ ] `POST /api/payment/create-order` 创建订单。
- [ ] `POST /api/payment/callback` 支付回调。
- [ ] `POST /api/tools/:toolCode/run` 工具执行。
- [ ] `GET /api/tools/:toolCode/quota` 查询剩余额度。
- [ ] `GET /api/tools/history` 用户工具历史。
- [ ] `GET /api/admin/metrics` 运营指标。

## 7. 数据表草案（MVP）
- [ ] `users(id, phone/email, password_hash, nickname, industry, city, created_at)`
- [ ] `plans(id, code, name, price, cycle, status)`
- [ ] `subscriptions(id, user_id, plan_code, start_at, end_at, status)`
- [ ] `orders(id, user_id, plan_code, amount, channel, status, paid_at)`
- [ ] `tool_usage(id, user_id, tool_code, date, count, success_count, fail_count)`
- [ ] `tool_results(id, user_id, tool_code, input_json, output_json, token_used, created_at)`
- [ ] `audit_logs(id, actor_id, action, target, detail_json, created_at)`

## 8. 风险清单与应对
- [ ] GPT 成本超预期：对长文本功能加 token 上限与队列控制。
- [ ] 支付回调异常：签名校验 + 幂等 + 补偿任务。
- [ ] 免费刷量：IP + 账号双限流、行为风控分。
- [ ] 结果质量不稳：Prompt 版本化 + 人工抽样复核。

## 9. 上线前检查（第 6 周）
- [ ] 安全检查：鉴权绕过、越权访问、敏感信息泄露。
- [ ] 性能检查：核心接口 P95 < 2.5s（计算类 < 500ms）。
- [ ] 兼容检查：移动端主流机型 + PC 主流浏览器。
- [ ] 可观测性：日志、告警、看板可用。
- [ ] 灰度发布：10% 用户灰度 24h，无重大故障后全量。

## 10. 发布后 2 周运营指标
- [ ] 注册转化率（访问->注册）目标 >= 12%。
- [ ] 免费用户次日留存目标 >= 25%。
- [ ] 免费->付费转化目标 >= 3%。
- [ ] 工具成功调用率目标 >= 98%。
- [ ] 工单平均响应时间目标 <= 12 小时。
