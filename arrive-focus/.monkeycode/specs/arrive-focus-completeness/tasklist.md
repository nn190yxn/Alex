# 需求实施计划

- [ ] 1. 建立全面修复的共享状态与验证基线
  - 梳理项目、任务、重复实例、便签、备份和 updater 的现有命令边界，记录每项修复对应的架构模块与数据约束。
  - 增加统一的前端数据 revision 或失效通知模型，定义项目、今日、日历、统计和小组件需要响应的写入事件。
  - [ ] 1.1 增加跨模块测试 fixture 与临时 SQLite 数据构造工具
    - 覆盖普通任务、项目任务、重复实例、专注记录、便签和周目标的最小完整场景。

- [ ] 2. 修复本地备份与恢复完整性
  - 扩展备份快照、导出、校验、恢复前快照和恢复事务，纳入 Memo Center/便签及其关联数据，符合 ARCHITECTURE.md 数据管理边界。
  - 为备份格式增加明确版本校验和未知字段处理策略，保证损坏文件在写入数据库前被拒绝。
  - 保证恢复失败时数据库、自动快照和运行时缓存保持原状态，并在恢复成功后广播统一数据变更事件。
  - [ ] 2.1 增加备份往返、损坏文件、版本不兼容和事务回滚测试
    - 验证便签、周目标和核心任务数据的完整往返及失败隔离。
  - [ ] 2.2 接通设置页本地数据入口
    - 按现有设置域约定启用导出、恢复、快照和清理操作，并提供进行中、成功和失败反馈。

- [ ] 3. 将重复规则和首批实例创建变为原子操作
  - 在 recurrence service/repository 中合并规则与首批实例写入，确保规则成功而实例失败时整个事务回滚。
  - 统一重复规则创建、模板任务引用和实例生成的错误码及边界校验。
  - [ ] 3.1 增加事务失败属性测试
    - 验证任意规则校验、模板引用或实例冲突失败后数据库不残留半成品。
  - [ ] 3.2 修复未来规则变更与实例状态保护
    - 保持 completed、skipped 和已有 focus session 的实例字段稳定；仅刷新 pending 且未开始的实例。
    - 明确并实现 effective_on 对未来规则、当前实例和历史实例的范围约束。

- [ ] 4. 完善重复实例生命周期与今日语义
  - 允许取消专注后的重复实例根据业务状态继续完成、跳过或顺延，并让所有可操作性 SQL 条件与 domain 状态一致。
  - 从 TodayDigest 和 CalendarPeriodResult 中过滤 skipped、rescheduled、removed 及未来不符合条件的来源。
  - 禁止归档项目启动新的普通任务或重复实例专注，并为项目状态校验补充统一服务入口。
  - [ ] 4.1 增加重复实例生命周期集成测试
    - 覆盖取消专注、完成、跳过、今日延后、顺延明日、规则结束和项目归档组合。

- [ ] 5. 修复任务、项目和重复操作的并发与重复提交
  - 为任务完成、恢复、删除、重复实例操作和项目删除增加按实体 ID 的前端忙碌态及命令返回后的状态收敛。
  - 保持 Rust 条件更新和唯一约束作为最终幂等边界，统一重复调用的成功语义与错误展示。
  - 校验项目删除、解除历史关联、归档和任务删除之间的历史保留规则，避免重复提交产生部分结果。
  - [ ] 5.1 增加并发操作与重复点击测试
    - 验证同一实体同时触发多次操作时只有一个有效状态转换，UI 最终状态与数据库一致。

- [ ] 6. 修复便签、周目标和跨日期竞态
  - 为便签保存增加请求序列号或版本校验，防止旧响应覆盖较新的跨日期内容。
  - 将选中日期、自然周和跨午夜变化纳入统一刷新触发器，保证连续跨日时日期条、任务、便签和周目标同步更新。
  - 保持便签 500ms 防抖与 Ctrl+Enter 立即保存语义，并在保存失败时恢复可重试状态。
  - [ ] 6.1 增加跨日期竞态和连续跨午夜测试
    - 验证快速切换日期、旧请求晚返回、连续跨两个日期边界时的数据不会串写或停留在旧日期。

- [ ] 7. 建立跨窗口和外部写入刷新链路
  - 将任务、项目、重复实例、专注完成、设置、备份恢复和小组件写入映射为统一事件或 revision 变化。
  - 让主窗口、WidgetApp 和日历/统计页面在外部窗口写入后重新获取权威 DTO，避免依赖局部 React 状态。
  - 处理事件监听初始化失败、重复订阅和窗口销毁清理，保持浏览器预览内存数据源可用。
  - [ ] 7.1 增加双窗口刷新集成测试
    - 覆盖主窗口完成任务、小组件完成任务、托盘完成专注、备份恢复后两窗口同时刷新。

- [ ] 8. 完善 Memo Center 与专注历史用户入口
  - 增加 Memo Center 的路由或工作区入口、列表/编辑/删除/恢复流程，并接入现有 planning/backup 数据边界。
  - 从数据库读取专注历史，补齐最近轮次、日期筛选和项目/任务关联展示，保持取消轮次统计口径不变。
  - 为空数据、加载失败、保存失败和恢复后刷新提供明确界面状态。
  - [ ] 8.1 增加 Memo Center 与专注历史组件测试
    - 覆盖入口可达、编辑保存、空状态、错误重试和跨窗口更新。

- [ ] 9. 修复 updater 配置与版本契约
  - 统一 tauri.conf.json、编译期环境变量和 update command 的 endpoint、公钥来源，避免生产构建落入 UPDATE_NOT_CONFIGURED。
  - 增加构建期非空校验，确保正式构建必须同时具备 updater endpoint 与公钥，开发构建保留可识别的禁用状态。
  - 校验补丁版本递增、latest.json、安装包签名和更新签名之间的版本一致性。
  - [ ] 9.1 增加 updater 配置与响应解析测试
    - 覆盖未配置、配置完整、版本比较、下载失败、验签失败和安装失败状态。
  - [ ] 9.2 完成 Windows 签名配置的安全接入
    - 将 updater 私钥和 Windows Authenticode 凭据仅通过 GitHub Secrets 注入 workflow，不写入仓库文件或构建日志。

- [ ] 10. 强化发布 workflow 和安装升级验证
  - 在根目录生效的 release workflow 中加入 typecheck、Vitest、Rust test、desktop feature test、fmt、Clippy 和前端生产构建门禁。
  - 增加 Windows runner 上的 NSIS 安装、升级、卸载、WebView2 前置条件和用户数据保留 smoke test。
  - 增加 updater 真实下载、验签、安装、重启和失败回滚验证，并在 workflow 中校验 release 资产完整性与 SHA-256。
  - 清理仓库子目录下不会生效且可能造成误判的嵌套 release workflow。
  - [ ] 10.1 增加发布产物契约测试
    - 验证安装器、签名文件、latest.json、版本号和校验值全部存在且相互匹配。

- [ ] 11. 完成分阶段质量检查点
  - [ ] 11.1 检查点 - 核心数据和重复任务修复通过
    - 确保相关 Rust 测试、迁移测试、Clippy、fmt、TypeScript 检查和前端测试通过，如有疑问请询问用户。
  - [ ] 11.2 检查点 - 前端刷新和桌面交互修复通过
    - 确保跨日期、跨窗口、Widget、托盘、专注和日历统计相关测试通过，如有疑问请询问用户。
  - [ ] 11.3 检查点 - 发布链路可交付
    - 确保 Windows 安装、升级、卸载、签名、updater 和数据保留验证通过，如有疑问请询问用户。

- [ ] 12. 建立回滚与兼容性保护
  - 增加数据库迁移失败保护、备份恢复前快照保留和应用升级失败后的用户数据恢复路径。
  - 为旧备份版本、旧数据库 schema 和旧 updater 响应保留明确兼容判断及可诊断错误码。
  - 确认每个补丁版本只包含已通过门禁的修复，并在发布脚本中阻止重复版本或缺少签名资产的 Release。
