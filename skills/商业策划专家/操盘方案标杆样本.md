# 操盘方案标杆样本

## 定位

本文件用于校准 `商业策划专家` 在处理操盘型概念方案时的输出方向。

当用户要求写项目定位、概念方案、整体操盘方案、商业策划方案，尤其是写字楼、公寓、底商、酒店、物业私域等多资产单元叠加项目时，必须先读取本文件，再进入撰写或优化。

本文件的核心作用是避免 skill 退化成“商业报告审查工具”或“语言去 AI 工具”。操盘型概念方案要像项目操盘人写出来：能判断、能假设、能招商、能运营、能分阶段落地。

---

## 一、标杆样本：方舟聚场最终稿

### 1. 样本价值

`方舟聚场` 最终稿的价值，不在于它已经是完整财务测算稿，而在于它把项目从单一底商定位提升为混合业态资产激活方案。

它不是只写 1.17 万㎡底商怎么做，而是把以下资产单元放在同一套经营系统里：

- 写字楼：10.5 万㎡、384 套、53 层、4.5m 层高
- 公寓：6.7 万㎡、1099 套、51 层
- 底商：1.17 万㎡、121 套、5 层
- 酒店：写字楼高区转化的高空河景生活方式酒店
- 物业私域：20 万业主、管家体系、物业 APP 和社群触达
- 外部客源：越界影城、歌剧院、学校、周边社区和未来 G7 商业

最终稿的关键不只是文字更自然，而是方案模型更准确：F3 是混合业态资产激活，不是单纯社区非标商业。

### 2. 主线结构

方舟聚场最终稿的主线是：

```text
项目本体 -> 区域市场 -> 混合业态属性 -> SWOT -> 辐射范围 -> 消费需求 -> 竞品格局 -> 对标案例 -> 项目定位 -> 双主力店 -> 五层业态 -> 写字楼/公寓/酒店定位 -> 物业联动 -> 时段经营 -> 分阶段落地
```

这个结构比普通商业报告更接近操盘方案。它不是只证明定位成立，而是把定位拆成各资产单元的经营动作。

### 3. 成立原因

最终稿更接近用户想要的方向，主要因为它做到了以下几点：

1. 先讲项目硬条件，再讲概念。
2. 先判断竞争关系，再提出差异化生存空间。
3. 先把楼上客群、社区客群和外部客群讲清楚，再安排业态。
4. 先确认写字楼、公寓、底商三者互相导流，再讲商业品牌。
5. 把对标案例转译成动作，而不是只列案例名。
6. 敢给具体经营假设，例如日均客流、月租、客单、阶段目标、运营频次。
7. 保留有记忆点的方案句，让甲方能快速理解经营逻辑。

## 二、可复用写法

### 1. 项目判断写法

操盘型概念方案需要明确、直接的判断。

可复用结构：

```text
F3 不是独立商业体，而是写字楼 + 公寓 + 底商的混合业态项目。商业是底商，服务于楼上的办公和居住人群。这一属性决定了 F3 商业规划的第一原则：商业不能脱离写字楼和公寓独立运作，三者必须在空间动线、客群组织和经营权益上形成联动。
```

这种写法的价值在于：

- 先重新定义项目属性。
- 再推出规划原则。
- 最后落到空间、客群、权益三类动作。

### 2. 竞品关系写法

操盘方案不能只写“差异化竞争”，要写清楚为什么不能正面竞争，以及应该从哪里切入。

可复用结构：

```text
G7 是 9.43 万㎡一站式购物中心，F3 底商可租赁面积 1.17 万㎡，仅为 G7 的 1/8。在 G7 覆盖全客群全时段的前提下，F3 不可能按综合商业路径与之竞争。G7 是大而全，F3 是小而精。差异不在日常与目的，而在体量和经营模式：G7 是标准购物中心逻辑，F3 是混合业态配套逻辑，楼上人下楼消费，公寓和写字楼的客流就是商业的日均保障。
```

这种写法的价值在于：

- 有竞品体量对比。
- 有竞争边界判断。
- 有经营模式差异。
- 有一句能被记住的判断：`G7 是大而全，F3 是小而精`。

### 3. 对标案例写法

操盘方案引用案例时，要把案例转成动作。

可复用结构：

```text
欢肆回答了“公寓 + 商业怎么联动”，安安和源野回答了“小体量怎么做差异”。F3 同时具备混合业态和非常规空间两个条件，方案需要同时解决两个问题。
```

这种写法比“可参考欢肆、安安、源野”更有效，因为它说明了：

- 每个案例分别解决什么问题。
- 本案为什么同时需要这些案例。
- 案例与本案之间的迁移关系。

### 4. 主力店替代写法

小体量项目常常缺少传统主力店，操盘方案要提出替代性主力内容。

可复用结构：

```text
1.17 万㎡可租赁面积无法承载传统主力店。F3 有两个空间可以替代传统主力店：一层方舟光庭承担日常展示和停留，B1 方舟漫坊·创想承担亲子、展陈和长期逗留。光庭和创想构成一日常一惊喜的双核心。
```

这种写法的价值在于：

- 先承认项目无法装传统主力店。
- 再提出替代逻辑。
- 最后形成容易理解的主力结构。

### 5. 楼层业态写法

操盘方案的楼层规划不能只写主题名，要写每层的经营任务。

可复用结构：

```text
食集是客流基础，日均 1,500 人用餐，餐后自然流向其他楼层。创想层是停留引擎，亲子和展陈让家庭待得住。光庭是门面，食集是日常，创想层是惊喜。
```

这种写法的价值在于：

- 每层都有经营角色。
- 不是单纯命名包装。
- 客流和停留关系清楚。

### 6. 物业联动写法

复合资产项目要重视物业私域，这是传统商业报告容易漏掉的抓手。

可复用结构：

```text
麓湖 8 年建社群，方舟的物业天然就是社群。20 万人的物业由中天自持，管家认识每户人家，知道谁家宝宝刚出生要托育，谁家老人独居要送餐。这一渠道条件同区域项目不具备。
```

这种写法的价值在于：

- 把物业从服务部门提升为商业获客通道。
- 把“私域流量”具体化为管家、家庭数据、社群和 APP。
- 说明同区域项目难以复制的优势。

### 7. 分阶段落地写法

操盘方案要有阶段目标，不能停留在愿景。

可复用结构：

| 阶段 | 时间 | 核心 | 目标 |
|------|------|------|------|
| 刚需先行 | 0-6 月 | 光庭 + 食集 + 便利 + 药店 + 物业站 | 日均客流 500+ |
| 体验添彩 | 6-12 月 | 创想层首展 + 亲子工坊 + 花房 + 健身 + 教室 | 日均客流 1,000+ |
| 亮点引爆 | 12-18 月 | Live + 酒店 + 第二季展 + 天际餐厅 | 日均客流 1,500+ |

这种写法的价值在于：

- 阶段清楚。
- 每阶段有具体动作。
- 每阶段有经营目标。

## 三、操盘型方案允许保留的表达

以下表达在普通审查意见里可能显得口语，但在操盘型概念方案中可以保留，因为它们能帮助甲方快速理解经营逻辑：

- 下楼即消费
- 空间本身就是主力店
- 中庭即主力店
- 品牌即展品
- G7 是大而全，F3 是小而精
- 吃在聚场，请客吃在 G7
- 光庭是门面，食集是日常，创想层是惊喜
- 亲子换频次，策展换流量，酒馆换夜间

保留这些表达的前提：

1. 表达必须服务经营判断。
2. 后文必须有数据、空间、业态或运营动作支撑。
3. 不能连续堆叠成口号。
4. 不能替代具体方案。

## 四、操盘型方案必须具体到的层级

处理类似 F3 的项目时，最终方案至少要具体到以下层级：

| 层级 | 必须回答的问题 |
|------|----------------|
| 项目本体 | 项目体量、各资产单元、层高、套数、铺位结构、车位、入口和动线是什么 |
| 市场依据 | 区域人口、收入、产业、写字楼、零售、酒店市场给了什么机会和约束 |
| 竞品关系 | 核心竞品是谁，体量和经营模式差异是什么，本案避开什么、抢什么 |
| 客群来源 | 楼内、公寓、社区、影城、歌剧院、学校和外部到访分别承担什么客流 |
| 对标案例 | 每个案例解决了什么问题，本案迁移什么动作 |
| 总定位 | 项目品牌、定位前提和差异化逻辑是什么 |
| 主力空间 | 传统主力店不足时，用什么空间或内容替代主力店 |
| 楼层规划 | 每层承担什么经营任务，业态和品牌如何落位 |
| 资产单元 | 写字楼、公寓、酒店如何分别定位，如何与底商互相导流 |
| 运营联动 | 物业、社群、APP、会员、积分、活动如何形成复访 |
| 时段经营 | 早间、午间、傍晚、夜间、周末分别由什么内容承接 |
| 分期落地 | 0-6 月、6-12 月、12-18 月分别做什么，目标是什么 |

## 五、反向校准：旧 skill 的偏差

旧版本 skill 容易出现以下偏差：

1. 把概念方案当成报告审查来处理。
2. 把操盘表达全部改成正式顾问腔。
3. 把 F3 只判断为社区非标商业，忽略写字楼、公寓、酒店和物业私域。
4. 只强调语言去 AI，忽略具体经营假设。
5. 案例映射停留在“可借鉴”，没有转成动作。
6. 过度追求克制，导致方案没有记忆点和可讨论性。

新版本 skill 在处理操盘型概念方案时，必须以本文件作为正例校准。
