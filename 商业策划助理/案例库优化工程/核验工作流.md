# 核验工作流

## 单案例流程

```text
领取队列任务
→ 阅读原始案例正文
→ 确认项目身份与别名
→ 搜索官方来源
→ 用专业媒体补充机制和表现
→ 建立证据记录
→ 填写案例卡
→ 判断可迁移要素和禁止迁移内容
→ 二次审查
→ 更新状态
```

## 搜索顺序

1. 项目方/开发商/运营方官网或官方公众号；
2. 政府、文旅、商务、统计等官方平台；
3. 主流媒体和专业商业地产媒体；
4. 公开采访、视频转录和社交平台仅作为补充线索。

搜索结果必须记录访问日期。来源无法公开访问、需要登录或内容互相矛盾时，不得直接升级为已核验。

## 状态升级

### 线索 → 部分核验

至少确认项目名称、城市和项目类型，且有一条 A/B 级来源支撑项目身份。

### 部分核验 → 已核验

必须确认：

- 项目身份和基本条件；
- 本案例要说明的核心商业机制；
- 至少一条可公开引用的来源；
- 可迁移要素与迁移前提；
- 禁止迁移内容或不确定边界。

### 任意状态 → 不采用

出现项目身份无法确认、核心内容为重复转载且无增量、来源冲突无法解决或案例对策划决策没有增量时，记录原因后转为不采用。

## 批次策略

- 每批 25 个案例，保留原始 `case_id`，不得重新编号。
- P0 批次优先处理高价值案例和已核验案例的结构化复审。
- 每个批次单独保留输入快照、核验记录和输出结果。
- 批次完成后运行字段完整性、重复项目、来源状态和迁移边界检查。

## 交付准入

案例只有在以下条件全部满足后，才可以复制到 Skill 的正式已核验案例库：

- 证据状态为 `已核验`；
- 核心事实有来源对应；
- 事实、判断和推测分开；
- 至少一个问题标签和一个机制标签；
- 已记录迁移条件和禁止迁移内容；
- 通过批次审查。
