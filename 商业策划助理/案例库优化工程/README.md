# 案例库优化工程

## 目标

在不修改 `commercial-planning-assistant/references/` 原始案例库的前提下，建立一个独立、可追踪、可回溯的案例库优化版本。当前纳入 **461 个待核验/已核验案例**，采用“全量分层、重点深挖”的方式推进。

- 原始案例正文：`source/感性城市案例库_待核验.md`
- 原始已核验案例：`source/已核验案例库.md`
- 索引快照：`data/case-index-snapshot.csv`
- 案例数量：461
- 已核验：3
- 待核验：458（含当前索引中尚未进入正式核验的案例）
- 原始案例按5个商业模型分类；24组存在重复项目（DG01-DG24，覆盖52个案例），需要在引用时去重。

## 优化原则

1. 原始资料只读，所有优化结果写入本目录。
2. 不把搜索摘要、视频转录或媒体推测直接写成已确认事实。
3. 每个新增事实都保留来源、发布日期、访问日期和支撑范围。
4. 案例不只按项目类型分类，还按“解决什么问题、采用什么机制、适用什么条件”分类。
5. 先完成全量结构化和分层，再对高价值案例深度核验。
6. 案例进入商业策划 Skill 前，必须通过本目录的核验准入。

## 阶段

### 阶段一：结构化（461个）

统一项目名称、城市、体量、空间类型、业态、商业问题、目标客群、经营目标、资产条件和迁移难度。无法从原始资料确认的字段留空，并标记待补录。

### 阶段二：分层（461个）

将案例分为 P0、P1、P2：

- P0：66个原始高价值案例、3个已核验案例，以及当前项目明确选中的案例；优先深度搜索。
- P1：与常见项目问题高度相关、资料完整度较高的案例；作为第二批核验对象。
- P2：仅作灵感参考或资料稀疏的案例；保留结构化信息，不优先投入搜索。

### 阶段三：核验与完善

官方来源优先，专业媒体补充。每个案例至少形成“项目事实、商业机制、经营结果/可观察表现、来源范围、可迁移要素、禁止迁移内容”六项记录。

### 阶段四：质量审查

检查重复项目、事实与来源对应关系、状态准入、迁移条件、分类一致性和引用可用性。通过后才同步回 Skill 的案例索引或已核验库。
