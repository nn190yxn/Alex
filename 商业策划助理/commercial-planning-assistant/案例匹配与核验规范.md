# 案例匹配与核验规范

## 使用边界

案例是支持本案判断的证据，不是可直接复制的答案。先从 `case-index.csv` 筛选候选，再按 `case_id` 读取正文；进入客户正文前必须遵守案例状态准入规则。

| 状态 | 内部质量记录 | 客户正文 |
|---|---|---|
| verified | 可记录与引用 | 可引用具体项目事实 |
| pending | 可作为待核验候选 | 不引用具体项目事实、名称或经营结果 |
| rejected | 记录否决原因 | 禁止引用 |

## 匹配评分

每个候选案例按以下维度评分，总分100分。缺少项目资料时，该维度记为“待判断”，不以主观推断补分。

| 维度 | 分值 | 判断依据 |
|---|---:|---|
| 商业模型匹配 | 30 | 资产类型、商业模型和核心经营模式是否相近 |
| 项目问题匹配 | 25 | 是否面对同类客流、空置、停留、夜间消费或资产提效问题 |
| 空间条件匹配 | 20 | 街区、盒子、滨水、园区、地下或复合资产等条件是否可比 |
| 客群匹配 | 15 | 主要消费客群、到访目的和消费频次是否相近 |
| 业态与经营目标匹配 | 10 | 业态组合、招商目标或经营结果是否具有参考价值 |

选择 Top 3 至 5 个候选案例。得分相近时，优先选择资料完整度高、状态为 `verified`、迁移难度较低的案例。每次选择必须在内部质量记录中记录得分、入选原因和淘汰原因。

## 人工补录字段

`references/case-enrichment.csv` 是人工维护的决策标签源。运行 `scripts/generate_index.py` 时会合并到索引，避免索引重建覆盖人工标注。

| 字段 | 说明 |
|---|---|
| target_problem | 案例适合解决的商业问题 |
| customer_type | 主要客群 |
| operation_goal | 主要经营目标 |
| asset_condition | 资产与空间前提 |
| scale_level | 规模等级 |
| investment_level | 投资强度 |
| migration_difficulty | 低/中/高，迁移实施难度 |
| verification_priority | P0/P1/P2，核验优先级 |

未核验字段保持为空，不填写推测性结论。

## 核验优先级

| 优先级 | 适用案例 |
|---|---|
| P0 | 已被当前项目选择、支撑关键定位判断、可跨项目复用且来源较完整 |
| P1 | 高频项目类型常用、与项目问题高度相关但尚未进入正文 |
| P2 | 仅作灵感或资料不足、适配度尚不明确 |

不追求一次核验全部案例；优先形成覆盖常见商业模型和关键问题的高价值 `verified` 案例池。

## 案例迁移记录

客户正文引用案例时，内部质量记录必须补齐：

| 案例事实 | 解决的问题 | 核心机制 | 可迁移要素 | 本案调整方式 | 迁移前提 | 不可迁移内容 |
|---|---|---|---|---|---|---|
| | | | | | | |

正文只说明与本案有关的事实和启示，不复述完整案例，也不将案例结论直接等同于本案方案。
