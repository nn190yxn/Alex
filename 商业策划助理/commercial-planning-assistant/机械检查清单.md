# 机械检查清单

本文件是交付前的机械性自检清单，仅包含可通过文本匹配完成的检查项。交付前读取，逐项检查。

专业判断类检查（章节信息增量、案例可迁移价值、分阶段路径合理性等）不在此清单中，由策划师或Agent做语义判断，详见文末"专业审查建议项"。

## 检查对象范围

不同检查项扫描不同文件，避免误报：

| 检查类别 | 扫描范围 | 说明 |
|---|---|---|
| 禁用词、第一人称、内部标签、机械化表达 | 仅客户正文.md | 客户版必须纯净且避免模板化表达 |
| 参数、命名、数据口径 | 客户正文.md 与 项目上下文.md 对照 | 检查正文与锁定值是否一致 |
| 决策回写 | 项目上下文.md 与 决策日志.md 对照 | 检查修改是否已回写、否决方向是否重复 |
## 执行方式

- 禁用词/第一人称/内部标签/机械化表达：在客户正文中逐词或逐句搜索匹配
- 参数/命名：从项目上下文.md提取锁定值，在客户正文中搜索，检查是否一致
- 数据口径：在客户正文中搜索同一指标的多个数值，检查是否只有一个口径
- 决策回写：从决策日志.md提取否决方向和修改记录，在客户正文中检查是否重复出现

后续可增加检查脚本自动输出：禁用词命中位置、内部标签命中位置、楼层名称出现次数、项目关键数字出现位置、同一指标的多个数字口径。

## 机械检查项（10项）

### 1. 参数一致

**检查对象**：客户正文 与 项目上下文.md对照

- [ ] 楼层编号与项目上下文.md锁定值一致
- [ ] 命名体系与项目上下文.md锁定值一致
- [ ] 面积数据与项目上下文.md锁定值一致

**执行方式**：从项目上下文.md提取楼层编号、命名体系和面积数据的锁定值，在客户正文中搜索，检查是否出现不一致的值。

### 2. 命名一致

**检查对象**：客户正文

- [ ] 同一空间/楼层/资产在全文使用同一名称
- [ ] 无混用旧名称和新名称的情况

**执行方式**：在客户正文中搜索项目上下文.md记录的所有命名，检查同一对象是否出现多个名称。

### 3. 数据口径一致

**检查对象**：客户正文 与 项目上下文.md对照

- [ ] 同一报告内同一数据只有一个口径
- [ ] 外部市场数据标注年份和来源
- [ ] 项目参数标注文件来源和确认日期

**执行方式**：在客户正文中搜索同一指标（如面积、套数、入住率等），检查是否出现多个不同数值。检查项目上下文.md的数据口径冲突表，确认已处理。

### 4. 来源完整

**检查对象**：客户正文

- [ ] 外部市场数据：年份、来源、数字三要素齐全
- [ ] 项目参数：文件名称、确认日期齐全
- [ ] 一手调研：调研日期、样本范围齐全

**执行方式**：在客户正文中搜索所有包含数字的判断句，检查是否标注了来源。

### 5. 禁用词零命中

**检查对象**：仅客户正文

- [ ] 无AI腔禁用词（赋能/链路/颗粒度/心智占领/情绪价值拉满/降维打击）
- [ ] 无通用禁用词（底盘/引擎/驱动流量/互喂/趋零/尚无先例/难以复制/只会/自身也承认/平台可查/极为罕见/核心经验/天然条件/关键约束）
- [ ] 空泛词（打造/引领/升级等）已补具体对象和结果
- [ ] "抓手""闭环"已补具体对象

**执行方式**：在客户正文中逐词搜索禁用词清单中的每个词，记录命中位置。

### 6. 第一人称零命中

**检查对象**：仅客户正文

- [ ] 无"我""我的建议是""我认为""我们可以"

**执行方式**：在客户正文中搜索第一人称相关词汇。

### 7. 客户正文无内部标注

**检查对象**：仅客户正文

- [ ] 客户正文文件不含证据分类标注（【已确认】/【综合判断】等）
- [ ] 客户正文文件不含"待验证""研究假设"等内部标记
- [ ] 客户正文文件不含决策日志摘要

**执行方式**：在客户正文中搜索【已确认】、【综合判断】、【研究假设】、【待核验】等标签字符串。

### 8. 决策日志已回写

**检查对象**：项目上下文.md 与 决策日志.md对照

- [ ] 决策日志中记录的否决方向未在客户正文重复
- [ ] 决策日志中记录的修改已回写至项目上下文.md
- [ ] 决策日志中标记的"影响章节"已回溯处理（标记为"需复核"或已修正）

**执行方式**：从决策日志.md提取否决方向列表，在客户正文中检查是否重复出现。从决策日志.md提取修改记录，在项目上下文.md中检查对应字段是否已更新。

## 检查结果处理

- 任何一项不通过，修正后重新检查对应项
- 检查不通过的内容不可交付

### 9. 案例引用检查

**检查对象**：客户正文 与 references/已核验案例库.md、内部质量记录.md对照

- [ ] 案例在正文中出现（搜索案例名称，确认正文中有引用）
- [ ] 每个案例引用包含"对本案"的启示（搜索"对本案"或近义表述）
- [ ] 案例引用未超出已核验案例库记录的事实范围
- [ ] 禁止迁移内容未出现在正文中（逐条对照案例的禁止迁移清单）
- [ ] 正文中无案例库内部标注（【综合判断】等）
- [ ] **客户正文不含pending状态案例**：客户正文中不得出现待核验案例库（感性城市案例库_待核验.md、候选案例待核验.md）中的案例。pending状态案例只能出现在内部质量记录中并标注"待核验"
- [ ] **内部质量记录中的pending案例已标注状态**：内部质量记录中引用的待核验案例必须标注"待核验"，不得表述为已确认事实

**执行方式**：从已核验案例库.md提取项目所属商业模型分类下的案例名称，在客户正文中搜索确认引用。对每个被引用的案例，提取其禁止迁移内容清单，在客户正文中搜索是否有违规迁移。从感性城市案例库_待核验.md和候选案例待核验.md提取案例名称，在客户正文中搜索确认没有pending状态案例泄露到客户正文。

### 10. 提案表达质检

**检查对象**：仅客户正文

- [ ] 关键段落明确指向项目、空间、楼层、客群或业态，不以泛化行业表述替代本案判断
- [ ] 关键判断至少落到空间、业态、招商或运营动作之一，并说明预期经营结果或成立条件
- [ ] 无连续使用“项目应”“首先”“其次”“因此”“同时”“对应到”等固定起句
- [ ] 无未被具体对象和结果承接的“品质、活力、体验、升级”等抽象词
- [ ] 无口号式收口、连续同构句式或为凑节奏形成的低信息排比

**执行方式**：先搜索上述高频起句和抽象词，记录命中位置；再逐段进行语义检查。命中不必然失败，但未能补充具体对象、动作、结果或条件时，必须重写。

## 专业审查建议项（非机械检查，由策划师或Agent做语义判断）

以下项目无法通过文本匹配完成，需要语义理解：

1. 每个章节是否有其他章节没有的信息增量
2. 案例是否具有可迁移价值和明确的适用条件
3. 判断是否因证据不足而被阻断（应标注为研究假设而非跳过）
4. 分阶段落地路径是否合理、前置条件是否标注
5. 业态品牌方向是否合理、是否有虚构品牌适配性
6. 排比判定（需区分"低信息增量排比"和"有独立支撑的分点列举"）
7. 章节深度是否与项目证据和决策价值匹配
