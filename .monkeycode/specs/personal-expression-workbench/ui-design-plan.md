# 个人表达工作台 UI 设计规划

## 1. 视觉方向

采用简洁清晰的标准工作台形态，使用浅色背景、白色内容面板、明确的边框和少量高亮色。默认主题使用专业蓝，预留明亮橙绿和紫蓝智能两套主题，三套主题共享布局、信息层级和交互，不改变用户对功能位置的认知。

视觉关键词：专业、明亮、清楚、可持续使用、具有个人工具感。

## 2. 全局布局

```text
┌──────────────────────────────────────────────────────┐
│ 左侧导航 │ 顶部工作区信息、行业、场景、表达档案、用户 │
│          ├───────────────────────────────────────────┤
│          │ 当前页面主工作区                           │
│          │ 内容面板、状态、编辑、对比和确认操作       │
└──────────────────────────────────────────────────────┘
```

- 桌面端左侧导航宽度约 240px。
- 主内容区最大宽度约 1440px，页面两侧保留呼吸空间。
- 重要操作使用主色按钮，次要操作使用文字按钮或浅色按钮。
- 状态色只表达状态：绿色代表已完成，橙色代表待确认，红色代表风险，蓝色代表进行中。
- 移动端将左侧导航折叠为顶部菜单，双栏内容切换为上下布局。

## 3. 页面规划

### 3.1 工作台首页

首页用于快速进入任务和查看系统状态。

核心区域：

- 欢迎区域：当前个人表达档案和最近更新时间。
- 快速操作：新建改写、添加写作样本、导入行业材料。
- 表达系统状态：规则数量、风格匹配度、待确认规则。
- 行业知识包：已完善、整理中和新增行业。
- 最近改写任务：标题、行业、场景、时间和任务状态。

首页需要让用户在 10 秒内找到“新建改写”，并理解当前系统已经学到了什么。

### 3.2 新建改写工作区

采用三栏工作区：

```text
左栏：任务设置
中栏：原文输入与候选稿
右栏：诊断、规则来源和确认操作
```

任务设置包括：

- 行业知识包
- 个人表达档案
- 写作场景
- 改写强度
- 目标篇幅
- 现实、虚构或混合内容类型

中栏支持原文粘贴、Markdown 输入和版本切换。右栏先展示材料诊断，生成后切换为规则命中和事实差异。

### 3.3 我的方案语言

这个页面不要求用户填写抽象的“我的文风”，而是展示系统从用户确认结果中提炼的规则。

页面分为：

- 表达总览：正式程度、句式完整度、策略导向、结果导向等维度。
- 常用结构：例如“调整对象 → 实施方式 → 经营结果 → 运营目标”。
- 常用表达：用户确认过的术语和方案句式。
- 避免表达：用户拒绝过的表达和 AI 化表达。
- 典型案例：原句、用户认可版本、规则解释。
- 规则版本：当前版本、历史版本和回滚入口。

每条规则都展示“来源样本”和“适用场景”。

### 3.4 行业知识库

行业知识库使用左侧行业列表加右侧知识内容的布局。

知识分类包括：

- 术语
- 概念
- 指标
- 判断关系
- 分析结构
- 案例
- 待确认内容

每个知识条目展示：

- 中性语义
- 行业常见表达
- 用户个人表达
- 来源材料
- 可信度
- 是否已确认

“用户个人表达”单独展示，避免用户误以为行业材料里的原句就是自己的语言。

### 3.5 内容诊断

内容诊断采用问题清单加正文定位的形式。

诊断卡片包括：

- 材料充足度
- 事实和数字锁定
- 段落推进情况
- 重复解释
- 无来源具体细节
- 行业术语准确性
- AI 化表达
- 个人方案语言匹配度

点击问题后，正文滚动到对应位置，并显示处理建议。风险级别分为“需要确认”“建议修改”和“参考提醒”。

### 3.6 版本对比

版本对比支持三种视图：

- 原文 / 候选稿
- 候选稿 / 用户定稿
- 原文 / 用户定稿

每个差异块显示修改原因和规则来源。用户可以接受单句修改、拒绝单句修改或把修改后的句子加入当前场景规则。

## 4. 关键交互

### 4.1 通过选择学习文风

系统每轮给出 2 至 3 个候选句，候选句保持相同的行业语义，只改变表达方式。用户选择“更像我”的版本，系统提炼句式和表达规则。

### 4.2 行业语义与个人表达分离

知识条目详情始终同时显示：

```text
行业语义：这个概念表达什么业务关系
方案写法：用户通常如何在方案中表达
个人写法：当前用户认可的表达方式
```

### 4.3 改写强度

- 轻度润色：保持段落和句式，只调整明显问题。
- 方案改写：按个人方案语言重组句子和段落。
- 深度重构：重新组织行业逻辑和交付结构，需要用户确认。

### 4.4 规则来源提示

修改原因使用标签展示：

- 个人表达
- 行业知识
- 当前场景
- 内容诊断
- 事实保护

用户可以关闭来源详情，但默认保留可解释入口。

## 5. 一期页面优先级

一期先完成：

1. 工作台首页
2. 新建改写工作区
3. 我的方案语言
4. 行业知识库基础版
5. 版本对比与反馈

内容诊断先以内嵌右侧面板实现，二期再扩展为独立页面。主题切换一期实现专业蓝和明亮橙绿，紫蓝智能作为视觉预览保留。

## 6. UI 验收标准

- 用户从首页进入新建改写最多需要一次点击。
- 用户可以始终看到当前行业、场景和个人表达档案。
- 用户可以区分行业知识、个人规则和场景规则。
- 用户可以从原文定位到每一条主要诊断。
- 用户可以逐条确认、拒绝或保存修改。
- 桌面端和移动端均能完成输入、生成、对比和确认流程。

## 7. 全阶段 UI 路线

### 二期：多行业与多场景

新增“行业切换器”和“场景组合器”。用户可以在顶部同时看到当前个人表达档案、行业知识包和交付场景，并能预览三者叠加后的规则优先级。

新增页面：

- 行业包管理：行业列表、版本、条目数量、待审核内容和最近更新。
- 场景管理：正式汇报、行业分析、公众号、内部沟通、口播等配置。
- 多版本生成：同一行业语义并列生成不同场景版本。
- 规则冲突中心：展示个人惯用表达与行业标准术语的冲突及处理结果。

交互重点：

- 支持拖拽调整规则优先级。
- 支持锁定行业术语后重新生成个人表达。
- 支持将一次改写保存为场景模板。
- 支持按行业和场景筛选历史任务。

### 三期：知识提炼与文档生产

工作台从单段文本升级为文档项目。

新增页面：

- 文档资料中心：PDF、DOCX、网页、Markdown 和批量文件导入。
- 材料阅读器：原文、提取结果、来源和知识条目并列展示。
- 行业框架编辑器：指标、概念、判断关系和案例之间的关联图。
- 批量诊断中心：按文档、项目和行业查看材料质量与风格问题。
- 长文生产工作区：章节树、段落状态、事实锁定、改写进度和最终导出。
- 来源追踪面板：每个判断和数据回到原始材料。

交互重点：

- 通过拖拽把材料片段加入行业知识包。
- 点击知识条目定位原始来源。
- 支持章节级重写和单段重写。
- 支持长文任务暂停、恢复和版本回溯。
- 支持 Markdown、DOCX 和 PDF 导出。

### 四期：外部调用与团队协作

工作台升级为个人和团队共用的表达基础设施。

新增页面：

- Skill 发布中心：生成完整 Skill、蒸馏版 Skill 和场景专用 Skill。
- API 管理中心：API Key、调用量、模型配置和调用日志。
- 插件连接中心：浏览器、编辑器、知识库和办公软件连接状态。
- 团队空间：成员、角色、共享行业包、共享场景和个人规则。
- 审核工作台：提交、评论、逐条修改、审批和发布。
- 审计中心：规则变化、文档版本、模型调用和导出记录。

交互重点：

- 用户选择要发布的个人规则和行业规则后生成 Skill。
- 团队管理员设置行业标准规则，成员保留个人表达层。
- 审核者可以只查看事实变化、术语变化或风格变化。
- 共享规则发布前必须经过版本确认。

## 8. 全阶段导航结构

```text
工作台
├── 首页
├── 新建改写
├── 文档项目
├── 我的表达
├── 行业知识
├── 场景配置
├── 内容诊断
├── 版本与审核
├── Skill 与 API
└── 设置与审计
```

一期导航保持精简，二期增加行业和场景，三期增加文档项目，四期增加外部调用与团队入口。功能增加时保持左侧主导航稳定，通过分组和权限控制降低复杂度。

## 9. 全阶段设计门禁

- 新增功能必须说明它影响行业语义、个人表达还是场景交付。
- 新增页面必须保留当前行业、个人档案和场景上下文。
- 知识库页面必须展示来源和确认状态。
- 改写页面必须保留原文、候选稿和最终稿的可追溯关系。
- 团队规则与个人规则必须使用不同的视觉标识和权限边界。
- 所有长流程页面必须提供加载、失败、暂停、恢复和历史版本状态。
