# 知档软件需求规格

Feature Name: `local-document-index`
Updated: 2026-07-24
Status: Confirmed scope, design in progress

## Introduction

知档是一款面向 Windows 10/11 个人用户的桌面资料管理工具。应用允许用户选择磁盘或目录，基于文件名、规范化文档名称、完整路径和文件时间建立本地索引，将散落在不同目录中的同主题文档智能归组，并按创建时间与最后修改时间展示全部版本。首版仅处理文件系统元数据，不提取或索引文档正文。

## Glossary

- **应用**：知档桌面软件。
- **索引源**：用户授权应用扫描的磁盘或目录。
- **文档文件**：扩展名符合当前索引规则的本地文件。
- **文件名**：包含扩展名的文件系统名称。
- **文档名称**：移除扩展名、版本标记和副本标记后得到的规范化名称。
- **主题**：用于聚合同一资料不同版本的索引单元。
- **版本标记**：文件名中的 `v1`、`1.0`、`V2.3`、`修订版`、`终稿`、日期等版本信息。
- **版本组**：归属于同一主题的文档文件集合。
- **最新创建**：版本组中创建时间最新的可访问文档文件。
- **最近修改**：版本组中最后修改时间最新的可访问文档文件。
- **智能归组**：应用根据文档名称、版本标记、扩展名和路径信息计算主题归属候选的过程。
- **人工修正**：用户对主题名称、版本归属、主题合并或主题拆分进行的明确调整。

## Requirements

### Requirement 1：索引源管理

**User Story:** 作为个人用户，我希望选择需要管理的磁盘或目录，以便控制知档索引范围。

#### Acceptance Criteria

1. WHEN 用户添加索引源，应用应允许用户选择一个可访问磁盘或目录。
2. WHEN 用户确认索引源，应用应保存索引源路径、显示名称、添加时间和扫描状态。
3. WHEN 用户添加路径重叠的索引源，应用应提示重叠范围并允许用户保留覆盖范围更大的索引源。
4. IF 索引源当前无法访问，应用应保留索引源配置并显示无法访问状态和最近成功扫描时间。
5. WHEN 用户暂停索引源，应用应停止该索引源的自动扫描并保留已建立的索引记录。

### Requirement 2：文档发现与元数据索引

**User Story:** 作为个人用户，我希望应用发现索引源中的常见文档，以便统一检索散落的资料。

#### Acceptance Criteria

1. WHEN 应用扫描索引源，应用应递归发现符合扩展名规则的文档文件。
2. WHEN 应用发现文档文件，应用应记录文件名、文档名称、扩展名、完整路径、文件大小、创建时间和最后修改时间。
3. WHILE 应用建立首版索引，应用应仅使用文件系统元数据生成索引。
4. WHEN 用户修改文档扩展名规则，应用应在下一次扫描中应用新规则并更新索引结果。
5. IF 应用缺少目录或文件访问权限，应用应继续扫描其他可访问位置，并记录失败路径和失败原因。
6. WHILE 应用使用默认扩展名规则，应用应索引 `doc`、`docx`、`xls`、`xlsx`、`ppt`、`pptx`、`pdf`、`rtf`、`txt`、`md`、`csv` 和 `json` 文件。
7. WHEN 用户添加自定义扩展名，应用应校验扩展名格式并将有效扩展名加入索引规则。

### Requirement 3：文档名称规范化

**User Story:** 作为个人用户，我希望应用识别文件名中的版本和副本标记，以便找到同一资料的多个版本。

#### Acceptance Criteria

1. WHEN 应用索引文档文件，应用应从文件名中分离扩展名、版本标记、副本标记和规范化文档名称。
2. WHEN 文件名包含 `v1`、`V2.0`、`1.0`、`2.3.1` 等数字版本标记，应用应保存原始标记和可排序版本值。
3. WHEN 文件名包含 `副本`、`copy`、`修订版`、`最终版`、`终稿` 或日期标记，应用应保存对应标记并从规范化文档名称中移除该标记。
4. IF 应用无法识别版本标记，应用应保留完整文件名并使用最后修改时间参与版本排序。
5. WHEN 用户查看文档详情，应用应同时展示原始文件名和规范化文档名称。

### Requirement 4：主题索引与智能归组

**User Story:** 作为个人用户，我希望同一主题的文档自动集中展示，以便跨目录查看全部版本。

#### Acceptance Criteria

1. WHEN 应用完成文档名称规范化，应用应根据规范化文档名称、名称关键词、版本标记、扩展名和路径信息生成主题归属候选。
2. WHEN 多个文档具有相同规范化文档名称，应用应将多个文档归入同一版本组。
3. WHEN 多个文档名称高度相似且位于不同目录，应用应生成智能归组结果并标记归组置信度。
4. IF 智能归组置信度低于应用阈值，应用应创建独立主题并在待整理列表中提供合并建议。
5. WHEN 用户确认人工修正，应用应优先使用人工修正结果处理后续扫描发现的同路径文件。
6. WHEN 同一路径文件被重命名，应用应根据路径变化和元数据变化重新计算主题归属。

### Requirement 5：版本排序与最新版本识别

**User Story:** 作为个人用户，我希望版本按创建时间与最后修改时间清晰排序，以便判断最近生成和最近编辑的文件。

#### Acceptance Criteria

1. WHEN 用户打开主题，应用应按用户当前选择的时间维度从新到旧展示版本组中的文档。
2. WHEN 版本组包含多个文档，应用应将创建时间最新的可访问文档标记为“最新创建”。
3. WHEN 版本组包含多个文档，应用应将最后修改时间最新的可访问文档标记为“最近修改”。
4. WHEN “最新创建”和“最近修改”对应同一文档，应用应在同一版本条目中展示两个标记。
5. WHEN 多个文档具有相同当前排序时间，应用应依次按可排序版本值、另一时间维度和完整路径稳定排序。
6. WHEN 用户切换排序方式，应用应提供最后修改时间、创建时间、版本号和文件名排序选项。
7. WHEN 用户查看版本条目，应用应展示版本标记、最后修改时间、创建时间、完整路径和文件类型。
8. IF 带时间标记的文件当前无法访问，应用应显示文件状态，并在对应时间维度标记下一个可访问文档。

### Requirement 6：快速检索与结果展示

**User Story:** 作为个人用户，我希望通过名称、路径和时间查找资料，以便快速定位目标文档及其全部版本。

#### Acceptance Criteria

1. WHEN 用户输入检索词，应用应匹配主题名称、文件名、规范化文档名称和完整路径。
2. WHEN 用户设置时间条件，应用应支持按最后修改时间和创建时间筛选结果。
3. WHEN 用户设置位置条件，应用应支持按索引源和目录筛选结果。
4. WHEN 应用返回检索结果，应用应以主题为主结果，并展示版本数量、最新创建文件、最近修改文件、对应时间和所在位置。
5. WHEN 用户打开主题结果，应用应展示该主题的完整版本列表和排序控制。
6. WHEN 用户选择版本条目，应用应提供打开文件和打开所在目录操作。
7. IF 检索结果为空，应用应显示当前检索条件和清除筛选入口。

### Requirement 7：索引更新

**User Story:** 作为个人用户，我希望索引跟随本地文件变化更新，以便检索结果保持有效。

#### Acceptance Criteria

1. WHEN 应用启动，应用应检查已启用索引源的可访问状态和上次扫描状态。
2. WHILE 应用运行且索引源可访问，应用应监控新增、修改、重命名和移动事件并更新受影响记录。
3. WHEN 文件变化事件无法可靠关联，应用应重新扫描受影响目录。
4. WHEN 用户触发手动刷新，应用应扫描选定索引源并显示扫描进度、已处理文件数和失败数量。
5. IF 文档文件已经移出索引源，应用应将记录标记为缺失，并在用户确认清理后从活动索引中移除。

### Requirement 8：人工整理与归组修正

**User Story:** 作为个人用户，我希望修正系统的主题归组，以便索引符合个人资料组织方式。

#### Acceptance Criteria

1. WHEN 用户编辑主题，应用应允许修改主题显示名称。
2. WHEN 用户选择多个主题，应用应允许将多个主题合并为一个版本组。
3. WHEN 用户选择版本组中的文档，应用应允许将选中文档拆分到现有主题或新主题。
4. WHEN 用户完成合并或拆分，应用应立即重新计算版本数量、排序、“最新创建”和“最近修改”标记。
5. WHEN 后续扫描更新已人工整理的文档，应用应保留人工主题归属和主题显示名称。

### Requirement 9：本地数据与隐私

**User Story:** 作为个人用户，我希望知档数据保存在本机，以便离线使用并控制资料信息。

#### Acceptance Criteria

1. WHILE 应用运行，应用应将索引源、文档元数据、主题、版本关系和人工修正保存在本地。
2. WHILE 应用执行首版索引，应用应在本机完成扫描、归组、搜索和排序。
3. WHEN 用户查看隐私说明，应用应说明索引字段、扫描范围和本地存储位置。
4. WHEN 用户导出索引备份，应用应导出主题、版本关系、人工修正和索引源配置。
5. WHEN 用户恢复索引备份，应用应重新校验索引源和文件可访问状态。

### Requirement 10：性能与可用性

**User Story:** 作为拥有大量资料的个人用户，我希望扫描和检索过程保持可用，以便持续使用应用管理文件。

#### Acceptance Criteria

1. WHILE 应用执行首次扫描，应用应保持检索、浏览和取消扫描操作可用。
2. WHEN 索引包含 100,000 个文档记录，应用应在用户输入停止后的 500 毫秒内展示本地检索结果，测试设备基线为 4 核 CPU、8 GB 内存和 SSD。
3. WHEN 应用重新扫描未变化的索引源，应用应复用已保存的文件元数据并仅更新发生变化的记录。
4. IF 扫描任务异常中断，应用应保存已完成进度，并在下次扫描时继续处理未完成范围。
5. WHEN 应用显示扫描结果，应用应提供已发现文档数、已归组主题数、待整理主题数、失败路径数和扫描耗时。

### Requirement 11：安全删除与回收站

**User Story:** 作为个人用户，我希望在资料工作台中清理无用版本，以便减少重复文件并保留恢复机会。

#### Acceptance Criteria

1. WHEN 用户对单个文档执行删除，应用应显示文件名、完整路径和“移入 Windows 回收站”说明并请求确认。
2. WHEN 用户对多个文档执行删除，应用应显示文档数量、文件名摘要和受影响主题并请求确认。
3. WHEN 用户确认删除，应用应通过 Windows 回收站机制移动选中文档。
4. WHEN 文档成功进入 Windows 回收站，应用应更新文档可用状态、主题版本数量和双时间标记。
5. IF 文档移动到 Windows 回收站失败，应用应保留当前索引状态并显示系统错误说明。
6. WHEN 用户完成删除，应用应提供打开 Windows 回收站的入口。
7. WHILE 用户查看主题版本，应用应允许选择单个或多个版本执行回收站操作。

### Requirement 12：资料工作台与按需预览

**User Story:** 作为个人用户，我希望在同一个工作台中检索、选择和预览文件，以便减少应用切换并快速确认目标版本。

#### Acceptance Criteria

1. WHILE 用户使用主窗口，应用应使用左侧侧边栏和右侧工作区组成两栏主布局。
2. WHILE 用户查看右侧工作区，应用应在顶部提供统一搜索和筛选区域，并在下方提供可调宽度的文档列表与预览面板。
3. WHEN 用户选择文档，应用应在右侧预览面板按需加载该文档的只读内容。
4. WHILE 应用扫描或建立搜索索引，应用应排除预览读取到的正文内容。
5. WHEN 用户选择 PDF、TXT、Markdown、CSV、JSON 或常见图片文件，应用应使用内置预览器展示内容。
6. WHEN 用户选择 DOCX、XLSX 或 PPTX 文件，应用应使用对应的只读 Office 预览器展示内容和基础排版。
7. WHEN 用户选择 DOC、XLS 或 PPT 文件，应用应调用当前 Windows 已注册的预览处理程序尝试展示只读内容。
8. IF 文件类型缺少可用预览器，应用应展示文件信息，并提供“用默认程序打开”和“打开所在目录”操作。
9. WHEN 用户选择其他文档、折叠预览或关闭窗口，应用应释放当前预览资源。
10. WHEN 用户拖动工作区分隔线，应用应调整列表与预览宽度并保存用户偏好。
11. WHEN 用户展开预览，应用应允许预览面板占用工作区主要宽度或进入工作区全屏模式。
12. IF 文档超过对应预览器的安全大小限制，应用应显示文件大小和系统打开入口。

## Scope Decisions

- 首版支持用户指定磁盘或目录作为索引源。
- 首版检索字段包括文件名、规范化文档名称、完整路径、创建时间和最后修改时间。
- 首版不提取、不存储、不检索文档正文。
- 首版同时使用创建时间和最后修改时间标记版本状态，并允许用户切换默认排序维度。
- 首版使用元数据进行智能归组，并提供人工合并、拆分和主题重命名能力。
- 首版运行于 Windows 10/11。
- 首版默认索引 Office、PDF、RTF、TXT、Markdown、CSV 和 JSON，并支持自定义扩展名。
- 首版支持将选中文档移入 Windows 回收站，成功后同步更新索引。
- 首版采用“左侧侧边栏 + 右侧工作区”两栏主布局，工作区内部提供列表与预览分区。
- 首版预览覆盖 PDF、文本、Markdown、CSV、JSON、新版 Office 和常见图片；旧版 Office 使用 Windows 已注册预览处理程序。
- 预览内容仅在用户选择文件时按需读取，不进入搜索索引和持久化正文数据。

## Confirmed Decisions

- 首发系统为 Windows 10/11。
- 首版覆盖 Office、PDF、文本与数据文件，并提供自定义扩展名白名单。
- 版本列表同时提供创建时间和最后修改时间两个维度。
- 删除方式为移入 Windows 回收站。
- 主界面采用两栏主布局，右侧工作区包含可调节的列表与预览区域。
- 预览采用内置预览、Windows 预览处理程序和系统默认程序三级处理路径。
