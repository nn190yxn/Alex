# 知档生产力增强需求规格

Feature Name: `document-index-productivity-enhancements`
Updated: 2026-07-28
Status: Confirmed for design

## Introduction

本功能在知档 v0.1.0 的本地元数据索引、主题归组、文件预览和安全回收能力上，增加快捷操作、搜索增强、批量处理、托盘常驻、定时扫描、通知、统计、拖放、格式扩展、版本比较和开机自启能力。所有新增功能继续遵守本机离线、受控文件访问和正文零持久化边界。

## Glossary

- **应用**：Windows 本地资料索引桌面软件（知档）。
- **全局搜索快捷键**：在其他应用处于前台时唤起知档搜索窗口的系统级组合键。
- **应用内快捷键**：主窗口获得焦点时执行搜索、导航或关闭临时界面的组合键。
- **搜索历史**：保存在本机界面偏好中的最近搜索词集合。
- **匹配高亮**：搜索结果中标识查询词命中位置的安全文本标记。
- **批量操作**：对多个已选文档一次执行复制路径、定位或元数据导出的操作。
- **托盘常驻**：主窗口关闭后隐藏窗口并保留后台文件监听与扫描服务的运行状态。
- **扫描计划**：用户启用的周期性全量扫描配置。
- **索引统计**：按来源、扩展名、可用状态、归组置信度和文件大小聚合的本机元数据指标。
- **版本比较**：比较同一主题内两个文档版本的元数据与可安全读取文本差异。

## Requirements

### Requirement 1：快捷搜索与键盘操作

**User Story:** 作为经常查找本地资料的用户，我希望通过快捷键唤起并操作应用，以便减少鼠标操作和窗口切换。

#### Acceptance Criteria

1. WHEN 用户按下已注册的全局搜索快捷键，应用应显示主窗口、切换到搜索工作台并聚焦搜索输入框。
2. WHEN 用户在主窗口按下 `Ctrl+K`，应用应聚焦搜索输入框并保留当前查询。
3. WHEN 用户在主窗口按下 `Ctrl+1` 至 `Ctrl+5`，应用应切换到对应主导航工作区。
4. WHEN 用户按下 `Escape`，应用应按预览全宽、临时确认层、展开详情和搜索输入的优先顺序关闭当前临时状态。
5. IF 全局快捷键注册失败，应用应继续启动并在设置页显示快捷键冲突状态。

### Requirement 2：搜索历史与匹配高亮

**User Story:** 作为重复查找相似资料的用户，我希望复用历史查询并看到匹配位置，以便更快判断搜索结果。

#### Acceptance Criteria

1. WHEN 有效非空搜索完成，应用应将查询词写入最多 20 条的本机搜索历史并合并重复项。
2. WHEN 用户聚焦空搜索框，应用应展示按最近使用时间排序的搜索历史。
3. WHEN 用户选择历史项，应用应恢复对应查询词并执行搜索。
4. WHEN 用户清除单条或全部搜索历史，应用应立即更新本机记录和历史列表。
5. WHEN 搜索结果命中主题名、文件名、规范化名称或路径，应用应在结果中高亮对应查询词或显示安全匹配片段。
6. IF 搜索词包含 FTS5 特殊字符或 HTML 字符，应用应以纯文本方式展示高亮并保持查询可执行。

### Requirement 3：文档批量操作与元数据导出

**User Story:** 作为整理多个文档版本的用户，我希望批量复制路径、定位文件和导出元数据，以便在其他工具中继续处理。

#### Acceptance Criteria

1. WHEN 用户选择一个或多个可用文档，应用应提供批量复制完整路径操作。
2. WHEN 用户选择一个或多个可用文档，应用应提供批量打开所在目录操作。
3. WHEN 用户选择一个或多个文档，应用应允许将文件名、主题名、完整路径、扩展名、大小、创建时间、修改时间和可用状态导出为 UTF-8 CSV。
4. WHEN 批量定位的文档数量超过 10 个，应用应在执行前显示数量确认。
5. IF 某个文档在批量操作前变为不可用，应用应继续处理其他有效文档并返回逐项结果摘要。

### Requirement 4：系统托盘与窗口生命周期

**User Story:** 作为持续使用索引监听的用户，我希望关闭主窗口后应用继续在托盘运行，以便文件变化持续进入索引。

#### Acceptance Criteria

1. WHEN 用户关闭主窗口，应用应隐藏主窗口并保持文件监听和活动扫描运行。
2. WHEN 用户点击托盘图标或选择“显示主窗口”，应用应恢复并聚焦主窗口。
3. WHEN 用户从托盘选择“立即扫描”，应用应扫描全部已启用且可访问的索引源。
4. WHEN 用户从托盘选择“退出”，应用应释放预览、监听和托盘资源并结束进程。
5. WHILE 扫描运行，托盘菜单应显示扫描状态并阻止重复启动同一全量扫描。

### Requirement 5：定时扫描与桌面通知

**User Story:** 作为长期维护知档的用户，我希望配置周期扫描并接收完成通知，以便索引在后台保持最新。

#### Acceptance Criteria

1. WHILE 扫描计划保持默认状态，应用应保持扫描计划关闭。
2. WHEN 用户启用扫描计划，应用应支持每日指定时间或每隔 6、12、24 小时执行全量扫描。
3. WHEN 扫描计划到期且已有扫描运行，应用应跳过本次计划并记录下次执行时间。
4. WHEN 后台扫描完成或失败，应用应在获得系统通知权限后发送包含处理数和失败数的桌面通知。
5. IF 通知权限被拒绝，应用应继续扫描并在应用内状态栏保留结果。
6. WHEN 用户修改扫描计划，应用应持久化配置并即时重排下一次执行时间。

### Requirement 6：索引统计仪表盘

**User Story:** 作为管理大量资料的用户，我希望查看索引构成和健康状态，以便发现缺失文件、异常来源和存储集中区域。

#### Acceptance Criteria

1. WHEN 用户打开统计工作区，应用应展示文档数、主题数、总文件大小、待整理数和失败数。
2. WHEN 统计数据可用，应用应按索引源、扩展名、可用状态和归组置信度展示聚合分布。
3. WHEN 用户选择统计分组项，应用应将对应来源、扩展名或状态带入搜索工作台筛选。
4. WHILE 扫描运行，应用应使用最近完成的权威统计并标记当前数据更新时间。
5. IF 某个聚合维度没有数据，应用应显示可操作的空状态并保持其他统计可用。

### Requirement 7：拖放添加索引源

**User Story:** 作为首次配置索引的用户，我希望将目录拖入应用，以便快速添加索引位置。

#### Acceptance Criteria

1. WHEN 用户将一个或多个目录拖入索引位置工作区，应用应复用现有来源校验流程添加目录。
2. WHEN 用户将文件与目录混合拖入应用，应用应仅提交目录并说明被忽略的文件数量。
3. IF 拖入目录与已有索引源重叠或不可访问，应用应显示对应逐项错误并继续处理其他目录。
4. WHEN 来源添加成功，应用应启动对应来源的首次扫描并刷新来源列表。

### Requirement 8：扩展文件格式覆盖

**User Story:** 作为管理多种资料格式的用户，我希望索引和预览更多常见格式，以便减少资料遗漏。

#### Acceptance Criteria

1. WHILE 默认扩展名规则生效，应用应增加 `odt`、`ods`、`odp`、`epub`、`eml`、`svg`、`xml`、`yaml`、`yml` 和 `toml`。
2. WHEN 应用扫描新增格式，应用应继续仅持久化文件系统元数据。
3. WHEN 用户预览 ODT、ODS、ODP、EPUB 或 EML，应用应在安全大小和解压限制内生成只读分段文本。
4. WHEN 用户预览 SVG、XML、YAML、YML 或 TOML，应用应以安全文本或图像方式展示内容。
5. IF 新增格式内容损坏、超限或引用外部资源，应用应阻止外部资源加载并显示受限预览状态。

### Requirement 9：版本比较

**User Story:** 作为判断文档版本差异的用户，我希望比较同一主题中的两个版本，以便快速确认变化。

#### Acceptance Criteria

1. WHEN 用户在同一主题选择两个文档版本，应用应提供版本比较入口。
2. WHEN 比较开始，应用应展示文件名、路径、大小、创建时间、修改时间、版本标记和可用状态差异。
3. WHEN 两个版本均为安全文本格式，应用应展示有界的逐行新增、删除和未变化片段。
4. WHEN 任一版本属于非文本格式，应用应展示元数据差异和并排预览入口。
5. IF 任一版本不可用、超限或内容无法解析，应用应保留可用元数据比较并说明内容比较受限原因。
6. WHILE 比较会话关闭，应用应释放两个版本的临时正文和预览资源。

### Requirement 10：开机自启

**User Story:** 作为依赖后台索引监听的用户，我希望按需启用开机自启，以便登录 Windows 后自动恢复索引服务。

#### Acceptance Criteria

1. WHILE 开机自启保持默认状态，应用应保持开机自启关闭。
2. WHEN 用户启用开机自启，应用应注册当前用户级 Windows 登录启动项。
3. WHEN 应用由开机自启启动，应用应以托盘常驻方式启动并保持主窗口隐藏。
4. WHEN 用户关闭开机自启，应用应移除由应用创建的当前用户级启动项。
5. IF 系统拒绝修改启动项，应用应保持原设置并显示稳定错误状态。

### Requirement 11：增强偏好备份与恢复

**User Story:** 作为迁移索引配置的用户，我希望增强功能偏好随备份恢复，以便保留熟悉的使用方式。

#### Acceptance Criteria

1. WHEN 用户导出索引配置备份，应用应包含快捷键、扫描计划、通知、托盘行为和开机自启偏好。
2. WHEN 用户恢复包含增强偏好的备份，应用应校验并应用所有已知偏好。
3. WHEN 用户恢复缺少增强偏好的历史备份，应用应使用关闭扫描计划、关闭开机自启和默认快捷键补全配置。
4. IF 备份包含无效增强偏好，应用应在替换当前索引配置前拒绝恢复。
