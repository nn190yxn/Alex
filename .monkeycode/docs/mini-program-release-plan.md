# 小程序首发收口与全链路审查开发计划

## 1. 目标

本期目标是把当前小程序收口成一版适合尽快提审的首发版本，同时为二期语音能力和 `WechatSI` 插件接入保留清晰扩展路径。

本期目标：

1. 形成一版可提审的员工端小程序首发包。
2. 下线问卷功能。
3. 取消积分兑换功能，建议同时下线整个积分页。
4. 收口页面范围，降低录音、WebView、外部内容带来的审核复杂度。
5. 补齐隐私合规、权限授权、文案一致性。
6. 形成二期语音能力改造方案，后续接入 `WechatSI`。

本期首发保留模块：

- 登录与协议
- 首页
- 学习中心
- 制度中心
- 知识库
- 通知与待办
- 工作量日报
- 我的页面基础能力

本期暂缓模块：

- 问卷
- 积分
- 考试
- 演练
- 通关
- 评估中心
- WebView
- 销售录音复盘

## 2. 总体实施策略

采用四阶段推进：

1. 备份与基线冻结
2. 页面与功能收口
3. 合规与体验修复
4. 联调、自测、提审准备

每个阶段都保留明确回撤点，确保问题可快速恢复。

## 3. 备份方案

备份目标是保证三个层面的可恢复性：代码、配置、提审范围。

### 3.1 代码备份

- 创建独立修复分支，例如 `fix/miniprogram-release-hardening`
- 对当前 `real_sync/mini-program/` 目录建立一次完整基线快照
- 输出一份页面路由清单快照
- 输出一份当前隐私采集项清单快照

建议备份内容：

- `real_sync/mini-program/app.json`
- `real_sync/mini-program/pages/`
- `real_sync/mini-program/utils/`
- 协议页面
- 当前提审相关截图和说明文案

### 3.2 配置备份

- 备份 `project.config.json`
- 备份当前页面注册列表
- 备份 tabBar 配置
- 备份现有 API 域名与上传链路配置

### 3.3 业务备份

- 形成一份“当前上线功能地图”
- 形成一份“当前敏感能力清单”
- 形成一份“页面入口到目标页映射表”

### 3.4 备份验收标准

- 任意页面路由能从快照中恢复
- 任意协议文案能从快照中恢复
- 任意被下线模块能单独恢复

## 4. 详细开发计划

- 回撤基线点

## 5. 二期规划：WechatSI 接入方案

二期目标是恢复语音交互能力，并优先实现语音转文字输入。

前置条件：

1. 确认小程序主体支持 `WechatSI`
2. 确认插件可在后台添加
3. 确认版本和基础库要求满足条件

推荐接入顺序：

1. `pages/drill/free-chat/free-chat`
2. `pages/drill/doing/doing`
3. `pages/exam/exam`

原因：

- 这三类页面属于“语音输入转文字”
- `WechatSI` 天然适合直接返回 `res.result`
- 可以替换当前“录音文件上传后再转写”的中间链路

保留后续单独处理的页面：

- `pages/skill/record/record`

原因：

- 该页面核心价值是上传整段录音做 AI 复盘
- 它需要保留原始音频文件
- 更适合独立设计录音上传、分析、隐私说明和审核口径

二期交付物：

- 插件声明
- 录音转文字统一能力封装
- 录音权限说明
- 语音转文字错误处理机制
- 语音模块专项验收清单

## 6. 回撤方案

回撤按“页面、能力、版本”三层设计。

### 6.1 页面级回撤

适用场景：

- 单个模块改坏
- 某个页面触发提审风险

方案：

- 恢复对应页面注册
- 恢复页面入口
- 恢复页面代码快照

### 6.2 能力级回撤

适用场景：

- 隐私授权流程影响现有上传
- 登录说明调整引发流程异常

方案：

- 回退到基线分支对应文件
- 保持页面存在，仅关闭新能力入口
- 保留原稳定能力链路

### 6.3 版本级回撤

适用场景：

- 本轮修复整体不稳定
- 提审前发现大面积问题

方案：

- 直接回切到备份基线分支
- 用基线重新创建修复分支
- 分批重新并入已验证模块

### 6.4 回撤控制要求

- 每完成一个模块单独提交一次
- 每次提交对应一个明确主题
- 每个主题都能独立回退
- 保留变更说明和影响范围记录

## 7. 风险控制

主要风险：

1. 页面注册移除后残留跳转造成白屏
2. 隐私政策与实际采集项不一致
3. 图片上传权限流程影响日报提交
4. 首页或我的页面仍暴露已下线功能
5. 二期语音能力与首发版本边界混淆

控制措施：

1. 每移除一个页面，立刻全局扫描跳转引用
2. 每删除一类采集项，立刻同步更新隐私政策
3. 每改一处权限逻辑，立刻走真机流程验证
4. 每轮调整后更新“首发页面清单”
5. 首发与二期分支明确隔离

## 11. 审查原则

本计划的审查范围只针对 `real_sync/mini-program/` 小程序，不覆盖 Web 站点、宣传物料、PHP 页面和其他外围系统。

本轮工作的判断标准从“功能能上线”提升为“核心功能可稳定使用”。审查时必须同时满足以下原则：

1. 功能可达：用户能从合法入口进入目标页面。
2. 功能可用：页面主流程可以完成，不能停留在半成品或占位状态。
3. 数据闭环：页面输入、接口请求、服务端返回、前端展示、二次进入恢复都完整成立。
4. 异常可控：弱网、空数据、接口失败、权限拒绝、登录失效都有明确处理。
5. 合规一致：代码中的采集项、权限项、协议文案、提审说明逐项一致。
6. 可回撤：每类改动都可以独立恢复，不影响其他稳定模块。

## 12. 小程序全功能审查清单

### 12.1 账号与访问控制

审查对象：

- 登录页
- 用户协议页
- 隐私政策页
- 登录态恢复逻辑
- 退出登录逻辑

审查重点：

- 首次进入是否正确落到登录页或首页
- 协议未勾选时是否禁止登录且提示清晰
- 登录成功后 token、用户信息、设备信息是否正确写入存储
- 重新打开小程序时是否正确恢复登录态
- token 过期时是否统一回到登录页
- 退出登录后是否清空敏感缓存并回到登录页

验收标准：

- 登录成功、登录失败、协议未同意、token 失效、主动退出五种场景都表现稳定
- 不出现死循环跳转、空白页、已退出但仍可访问内部页的情况

### 12.2 首页与导航

审查对象：

- 首页
- tabBar
- 页面间跳转链路

审查重点：

- 首页是否只暴露首发范围内功能
- tabBar 五个入口是否都能打开且返回正确
- 被移出首发范围的模块是否还有残留入口
- 页面返回栈是否正常

验收标准：

- 所有首页入口、tabBar 入口、卡片入口都只通向首发保留页面
- 不存在跳往问卷、积分、考试、演练、评估、WebView、录音复盘的残留路径

### 12.3 学习中心

审查对象：

- 学习列表
- 学习详情
- 课程学习页

审查重点：

- 列表加载、分页或首屏展示是否正常
- 封面缺失时占位图是否正常
- 详情页字段为空时是否可展示
- 课程正文、图片、富文本是否渲染正常
- 从首页、通知或其他页面跳入时参数是否完整

验收标准：

- 列表、详情、课程页在有数据、无数据、字段缺失三种情况下都能稳定显示

### 12.4 制度中心

审查对象：

- 制度列表
- 制度详情
- 制度搜索

审查重点：

- 搜索关键词为空、命中、无结果时的表现
- 制度详情的标题、摘要、正文、附件链接展示是否正常
- 返回上一页后搜索状态是否符合预期

验收标准：

- 搜索和详情链路完整，无异常闪退和空白页

### 12.5 知识库

审查对象：

- 知识库列表
- 知识库详情

审查重点：

- 分类筛选、关键字搜索、详情打开是否正常
- 无封面、无摘要、无图文时的兜底展示是否合理
- 富文本或 Markdown 渲染是否可读

验收标准：

- 主要内容均可浏览，字段缺失不会破坏页面结构

### 12.6 通知与待办

审查对象：

- 通知列表
- 通知详情

审查重点：

- 已读未读状态展示是否一致
- 列表进入详情后返回列表是否能保持位置或状态
- 通知正文异常长、为空、带链接时的表现

验收标准：

- 通知链路可完整使用，状态展示与返回逻辑稳定

### 12.7 工作量日报

审查对象：

- 日报模板加载
- 门店信息与角色信息
- 指标填写
- 暂存
- 提交
- 图片凭证上传、预览

审查重点：

- 首次进入是否能正确拿到模板与本人门店信息
- 指标默认值、编辑值、回显值是否一致
- 暂存后再次进入是否能正确恢复数据
- 提交前校验是否准确
- 图片上传权限、上传成功、上传失败、取消选择、超限文件、超大小文件是否处理完整
- 提交后状态与管理端查看是否一致

验收标准：

- 日报从填写到暂存到提交到复查形成完整闭环
- 图片凭证流程稳定，失败提示明确，已上传内容可预览

### 12.8 管理视角日报

审查对象：

审查重点：

- 日期筛选是否正确
- 列表统计与详情数据是否一致
- 缺失数据、未提交数据、已提交数据状态是否清楚

验收标准：

- 管理端可完整查看员工日报数据，不出现状态错乱

### 12.9 我的页面

审查对象：

- 个人资料展示
- 清理缓存
- 版本信息
- 退出登录

审查重点：

- 页面是否只保留正式能力
- 清缓存后是否保留必要登录数据
- 退出登录后的缓存与页面访问是否正确受控

验收标准：

- 我的页面不存在“功能开发中”类占位入口
- 清缓存和退出登录行为可预期

## 13. 全链路审查矩阵

### 13.1 页面链路

每个首发页面都要按以下链路审查：

1. 入口来源
2. 路由参数
3. 页面初始化
4. 首屏加载
5. 用户操作
6. 数据提交或跳转
7. 结果反馈
8. 再次进入恢复
9. 返回上一页

要求：

- 任一链路都要覆盖“正常路径、空数据路径、失败路径”三套结果

### 13.2 接口链路

每个核心接口都要审查以下项目：

1. 请求参数是否完整
2. 未登录请求是否统一拦截
3. 成功返回码和业务失败码是否都被处理
4. 返回字段缺失时前端是否有兜底
5. 超时、弱网、服务端异常时提示是否清晰
6. 重试逻辑是否安全

重点接口组：

- 登录与登录态检查
- 首页聚合数据
- 学习列表与详情
- 制度列表、详情、搜索
- 知识库列表与详情
- 通知列表与详情
- 工作量模板、我的日报、保存日报、提交日报、凭证上传、凭证列表、凭证删除

### 13.3 权限链路

本期至少完整审查图片上传权限：

1. 首次调用前的权限状态
2. 用户同意授权后的续接行为
3. 用户拒绝授权后的提示与可恢复路径
4. 已授权后的重复调用
5. 系统设置页返回后的再次尝试

二期预审项：

- 录音权限
- 语音转文字能力

### 13.4 状态链路

需要重点检查以下状态切换：

- 未登录 -> 已登录
- 已登录 -> token 过期
- 日报未创建 -> 草稿 -> 已提交
- 图片未上传 -> 上传中 -> 上传成功 / 上传失败
- 列表无数据 -> 有数据
- 缓存已存在 -> 清除缓存后重新进入

要求：

- 每个状态切换都要能解释数据来源、界面表现和回退逻辑

## 15. 核心功能可用性验收标准

核心功能是否可用，必须同时满足以下标准：

1. 页面可访问：从真实入口可以进入。
2. 数据可加载：首屏不会因缺字段直接崩溃。
3. 主操作可完成：用户能完成页面最核心动作。
4. 结果可验证：提交后能看到成功结果或后续页面数据变化。
5. 异常可恢复：失败后有重试、返回、重新进入等恢复路径。
6. 状态可持续：重新进入页面后状态与上次操作一致。

不满足任一项，都不能定义为“功能正常使用”。

## 17. 回撤细化要求

### 17.1 回撤前提

- 每个模块独立提交
- 每次提交都记录变更文件、影响页面、影响接口、影响数据项
- 页面收口、协议文案、权限逻辑、日报链路分别独立提交

### 17.2 回撤分级

P0 回撤：

- 登录
- token 处理
- app.json 页面注册
- tabBar

P1 回撤：

- 首页入口
- 学习、制度、知识库页面
- 通知页面

P2 回撤：

- 文案优化
- 协议非关键描述
- 样式调整

### 17.3 回撤验收

- 回撤后项目可启动
- 登录和首页可正常进入
- 日报主链路不受影响
- 不引入新的死链和空白页

## 18. 阻塞级问题定义

以下问题属于阻塞级，任一存在都不进入提审：

1. 登录、退出登录、登录态恢复异常
2. 首页或 tabBar 存在死链
3. 首发页面仍跳到已下线模块
4. 日报无法暂存或提交
5. 图片上传流程不可用
6. token 失效后不能统一回登录
7. 隐私政策与实际采集项不一致
8. 存在明显“功能开发中”或不可用入口
