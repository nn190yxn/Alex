# AI 应用路由与真实生成链路收口开发计划

## 目标

本计划用于收口我赢 AI 网站本体中所有需要 AI 回答的页面，重点解决“页面能打开、路由存在，但实际生成仍走前端模板、后端硬编码或占位结果”的问题。后续开发必须先审计、再分类、再逐项修复，避免重复修改已经完成的真实 AI/RAG 链路。

## 1. 开发要求

### 1.1 先分类再修复

每个 AI 页面必须先归入以下四类之一：

| 分类 | 定义 | 处理方式 |
| --- | --- | --- |
| 真实 RAG/AI | 前端请求后端，后端调用 AI、RAG 或统一生成引擎 | 只验证，不重复改 |
| 后端规则兜底 | 前端请求后端，后端返回规则结构化结果 | 评估是否需要升级 AI 主链路 |
| 前端本地模板 | 前端直接拼接结果或用固定公式生成 | 优先修复 |
| 占位/未实现 | 页面、路由或返回结构存在占位 | 优先修复 |

### 1.2 每次只处理一个小批次

- 每批最多处理 2-3 个页面。
- 同一批优先选择同一业务域，例如抖音标题、抖音封面、抖音脚本。
- 每批完成后更新审计文档、运行验证、记录结果。

### 1.3 优先复用已有链路

- 通用工具优先复用 `/api/generate/:toolCode`。
- 抖音行业专版优先复用已有 `douyin-education`、`douyin-restaurant`、`douyin-service`、`douyin-beauty` RAG 配置。
- 独立智能体优先补强 `/api/douyin/*`、`/api/xhs/*`、`/api/private/*` 已存在路由。
- 已有权限、配额、日志、兜底机制优先沿用。

### 1.4 前端职责保持清晰

- 前端只负责采集输入、调用 API、展示 loading、错误、升级提示和结构化结果。
- 前端不再新增大段业务生成模板。
- 前端可保留展示映射、字段兼容和轻量格式化。

## 2. 开发标准

### 2.1 后端标准

- 需要 AI 输出的路由应具备主生成链路和兜底链路。
- AI 输出优先要求 JSON 或稳定结构，前端可直接渲染。
- AI Key 缺失或 AI 调用失败时，返回可识别的规则兜底结果。
- 兜底结果必须包含 `isRuleFallback` 或同等可识别字段。
- 权限不足必须返回明确 `requiredLevel` 和升级提示。
- 禁止向用户暴露 API Key、JWT_SECRET、数据库密码、私钥内容。

### 2.2 前端标准

- 统一通过 `frontend/src/api/request.js` 或 `frontend/src/api/tool.js` 请求后端。
- 生成按钮必须有 loading 状态。
- 失败时必须展示用户可理解的错误信息。
- 权限不足时展示升级引导。
- 结果渲染必须兼容 AI 输出和规则兜底输出。
- 生成开始时清空上一轮结果，避免误读旧结果。

### 2.3 文档标准

- 每次修复后更新 `.monkeycode/docs/ai-agent-real-generation-fix-plan.md`。
- 每个页面记录：页面路径、后端路由、当前分类、修复状态、验证方式。
- 记录真实阻塞项，例如缺少测试账号、缺少 AI Key、线上尚未部署。

### 2.4 验证标准

- 后端改动后运行对应语法检查，例如 `node --check src/routes/douyinAgents.js`。
- 前端改动后运行 `npm run build`。
- 能本地预览时启动 Vite，并确认预览页面可访问。
- 接口验证至少覆盖成功、权限不足、AI Key 缺失兜底三类情况中的可执行项。

## 3. 开发边界

### 3.1 本轮纳入范围

- 抖音独立智能体页面：`frontend/src/views/douyin/*.vue`。
- 小红书独立智能体页面：`frontend/src/views/xhs/*.vue`。
- 私域独立智能体页面：`frontend/src/views/private/*.vue`。
- 后端独立路由：`backend/src/routes/douyinAgents.js`、`backend/src/routes/xhsAgents.js`、`backend/src/routes/privateAgents.js`。
- 通用生成路由：`backend/src/routes/generate.js`。
- 海报生成路由：`backend/src/routes/posterGenerator.js`。
- 诊断 V3 路由：`backend/src/routes/diagnosis.js`。

### 3.2 本轮冻结范围

- 宣传计划 HTML 和宣传计划 Markdown 不纳入本轮修复。
- 会员价格体系不纳入本轮重构。
- 首页、导航、视觉体系不纳入本轮重构。
- 线上服务器业务代码不直接盲改。
- 数据库结构不主动迁移，除非某个 AI 链路明确依赖。

### 3.3 禁止行为

- 禁止为了“看起来像 AI”继续增加前端硬编码模板。
- 禁止一次性大范围重构多个模块。
- 禁止修改无关页面或无关业务逻辑。
- 禁止覆盖用户已有未提交改动。
- 禁止读取、打印或写入真实密钥内容到文档或回复。

## 4. 开发约束条件

### 4.1 环境约束

- 本地无 AI Key 时，只能验证规则兜底、接口结构和前端渲染。
- 真实 AI 输出质量验证需要有效 AI Key 和可用登录态。
- 线上改动前必须先备份，改后端必须重启 `woying-backend`，改前端必须执行线上构建。

### 4.2 权限约束

- 免费、初阶、进阶、高阶页面必须符合现有权限矩阵。
- 前端入口锁定逻辑和后端权限拦截必须一致。
- 权限不一致时以后端权限为准，并记录需调整的前端入口。

### 4.3 输出约束

- 输出必须面向中小企业老板，避免技术化空话。
- 抖音输出必须包含短视频平台语境，例如前 3 秒钩子、完播率、互动率、私信、团购或留资。
- 小红书输出必须包含搜索、收藏、关键词、封面、笔记结构等平台语境。
- 私域输出必须包含客户分层、SOP、话术、复购、转介绍等经营语境。
- 所有结构化结果保留升级定制引导文案。

### 4.4 质量约束

- 优先做小而正确的改动。
- 新增 helper 仅在多个路由复用时使用。
- 不为兼容历史前端模板保留多套长期逻辑。
- 修复一个页面后必须能说明它从哪条链路生成结果。

## 5. 及时备份

### 5.1 本地备份

改动前必须确认当前工作区状态：

```bash
# 查看工作区变更
git status --short
```

若涉及大范围文件修改，应在 `.monkeycode/backups/` 下创建批次备份目录，命名格式：

```text
.monkeycode/backups/YYYYMMDD-ai-agent-route-convergence/
```

备份内容包括：

- 即将修改的前端页面。
- 即将修改的后端路由。
- 当前审计文档。
- 当前关键配置文件。

### 5.2 线上备份

线上改动前必须先创建服务器备份，建议目录：

```text
/home/ubuntu/woying-backups/YYYYMMDD-ai-agent-route-convergence
```

备份内容包括：

- `frontend/src/views/douyin/`
- `frontend/src/views/xhs/`
- `frontend/src/views/private/`
- `backend/src/routes/`
- 当前线上构建产物或部署目录快照

### 5.3 备份记录

每次备份后在修复文档记录：

- 备份时间。
- 备份路径。
- 覆盖文件范围。
- 对应修复批次。

## 6. 及时回撤

### 6.1 回撤触发条件

出现以下情况必须暂停继续开发并准备回撤：

- 前端构建失败且 3 次以内无法修复。
- 后端服务启动失败或核心健康检查失败。
- 已修复页面无法打开。
- 权限拦截异常，导致免费用户访问付费功能或正常会员无法访问。
- 线上用户核心路径受到影响。
- AI 输出结构无法被前端稳定渲染。

### 6.2 本地回撤原则

- 只回撤本轮修改文件。
- 保留用户和其他 Agent 的已有改动。
- 回撤前先查看 `git diff`，确认回撤范围。
- 禁止使用破坏性全局回滚命令。

### 6.3 线上回撤原则

- 使用本批次线上备份覆盖对应文件。
- 后端文件回撤后重启 `woying-backend`。
- 前端文件回撤后重新执行线上构建。
- 回撤后执行健康检查和目标页面验证。

### 6.4 回撤验证

回撤后必须验证：

- `https://woyai.cn/health` 正常。
- 受影响页面可打开。
- 原有功能恢复到回撤前状态。
- 错误日志无持续新增同类报错。

## 推荐执行节奏

1. 生成全量 AI 页面矩阵。
2. 标记四类链路状态。
3. 每批选择 2-3 个 `前端本地模板` 或 `占位/未实现` 页面。
4. 先备份，再改后端，再改前端。
5. 本地构建和语法验证。
6. 更新修复文档。
7. 需要上线时执行线上备份、部署、构建、重启和验证。
