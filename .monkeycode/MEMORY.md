# 用户指令记忆

本文件记录了用户的指令、偏好和教导，用于在未来的交互中提供参考。

## 格式

### 用户指令条目
用户指令条目应遵循以下格式：

[用户指令摘要]
- Date: [YYYY-MM-DD]
- Context: [提及的场景或时间]
- Instructions:
  - [用户教导或指示的内容，逐行描述]

### 项目知识条目
Agent 在任务执行过程中发现的条目应遵循以下格式：

[项目知识摘要]
- Date: [YYYY-MM-DD]
- Context: Agent 在执行 [具体任务描述] 时发现
- Category: [代码结构|代码模式|代码生成|构建方法|测试方法|依赖关系|环境配置]
- Instructions:
  - [具体的知识点，逐行描述]

## 去重策略
- 添加新条目前，检查是否存在相似或相同的指令
- 若发现重复，跳过新条目或与已有条目合并
- 合并时，更新上下文或日期信息
- 这有助于避免冗余条目，保持记忆文件整洁

[商业策划汇报语言口径]
- Date: 2026-09-11
- Context: 用户交付 6+7+8 号馆业态规划汇报终稿 PPT、对应全文和《商业策划汇报文字风格指南》
- Instructions:
   - 对内汇报口径：像资深招商运营负责人在陈述。A 是什么样，B 是什么样，两者是什么关系。
   - 标题即判断。看完标题就知道这页要说什么。
   - 「但是 / 然而 / 不过」改成「也 / 同时 / 并」，或拆成两句。
   - 事实自己说话，不加「独有」「核心优势」「别人复制不了」「最 / 第一 / 唯一」。
   - 「核心竞争力」是自我定位（我们靠什么竞争），属于陈述，保留；要删的是横向比较（核心优势）、绝对化（最 / 第一 / 唯一）与宣称他人做不到（独有 / 不具备 / 别人复制不了）。
   - 商业关系写成差异化定位。「竞品」写「同类项目」；「打赢」写「推进、落地」。
   - 写成双方分工、各自承担什么，不写我省了什么。
   - 用「我方」不用「我们」。行话能去就去：引擎、闭环、赋能、抓手、打法、打造、矩阵。
   - 叙事：先立标杆，再说为什么适合，再写谁落地、做成什么样、怎么合作。
   - 每页结论先行，优势劣势各写核心 3 条，先判断再跟事实。
   - 留有余地：较为、相对、约。租金谈判写「商务口径」，确实是底线才写「底线」。
   - 金样：当前工作区 `/personal-expression-preview/corpus/` 下的 6+7+8 全文与风格指南。
