## Phase B: 检索双通道升级 (已完成)

### B1. 向量检索索引构建
- 新建文件:
  - `backend/scripts/build-kb-index.js` - 切块(300-600chars) + TF-IDF 索引构建
  - `backend/src/services/vectorSearch.js` - 运行时向量检索服务
- 索引统计: 298 文件 → 2267 块 → 92052 词汇
- 输出: `backend/data/kb-index.json` (~20MB)

### B2. 双通道检索
- 修改文件:
  - `backend/src/services/kbService.js` - 新增 `getKBContextDualChannel()` 异步函数
  - `backend/src/services/engineRegistry.js` - `ragEngine` 支持 `retrievalMode` 选择
- 工作流程: mapping 过滤路径 → 向量检索 TopK → 上下文组装

### B3. 回滚开关
- 环境变量:
  - `KB_RETRIEVAL_MODE=mapping_only|mapping_plus_vector`
  - `KB_VECTOR_TOPK=8`
  - `KB_MAX_CONTEXT_CHARS=4500`
  - `KB_MAX_FILE_CHARS=1800`
  - `KB_CHUNK_MIN=300`
  - `KB_CHUNK_MAX=600`
  - `KB_CHUNK_OVERLAP=80`

### B4. 评测结果
- 评测集: 60 题 (3 行业 x 20 题)
- mapping_only: 整体 0.657, KB 利用率 83.3%, 平均上下文 1494 chars
- mapping_plus_vector: 整体 0.716, KB 利用率 95.0%, 平均上下文 2008 chars
- 双通道提升 5.9%, 上下文增加 34.4% (可通过调参优化)

## Phase C: 动态预算与分层优化 (已完成)

### C1. 动态上下文预算器
- 修改文件:
  - `backend/src/services/kbService.js` - 新增 `getDynamicContextBudget()`
- 策略: 会员等级 x 工具复杂度 x 输入长度 → 动态字符预算
- 预算范围:
  - free: 1000-2000 chars
  - starter: 1500-2500 chars
  - pro: 2500-4000 chars
  - annual: 3500-6000 chars

### C2. 动态 max_tokens 策略
- 修改文件:
  - `backend/src/services/kbService.js` - 重写 `getMaxTokensForLevel()`
- 工具类型乘数: diagnosis=1.5, rag=1.2, template=1.3, calculator=0.5, spreadsheet=0.8
- 示例: pro + restaurant-health(diagnosis) = 2400 tokens

## Phase D: 评测与发布保障 (已完成)

### D1. 标准评测集
- 文件: `backend/data/eval-dataset.json`
- 60 题覆盖: 餐饮(20)、美业(20)、教培(20)
- 每题包含: toolCode、formData、expectedKeywords、forbiddenOutput、scoringDimensions

### D2. 自动回归脚本
- 文件: `backend/scripts/eval-kb-retrieval.js`
- 使用方式:
  - `node scripts/eval-kb-retrieval.js mapping_only` - 单模式评测
  - `node scripts/eval-kb-retrieval.js mapping_plus_vector` - 双通道评测
  - `node scripts/eval-kb-retrieval.js --compare` - 双模式对比 + DoD 检查
- 输出: `backend/data/eval-report.json` + `backend/data/eval-comparison-report.json`

### D3. 发布门禁
- DoD 阈值:
  - 整体提升 >= 20%: 需优化（当前 5.9%）
  - 成本增加 <= 10%: 需优化（当前 34.4%）
- 回滚: 设置 `KB_RETRIEVAL_MODE=mapping_only` 立即切换

2. 部分工具（headline/schedule/membership-design）KB 映射为空，需补充 kb-mapping.json
3. DoD 整体提升 20% 目标尚未达成，需要更多评测题或优化检索算法
4. 前端反馈按钮尚未实现（后端 API 已就绪）

## 部署步骤
1. 构建 KB 索引: `node scripts/build-kb-index.js`
2. 部署所有修改文件到服务器
3. 设置环境变量: `export KB_RETRIEVAL_MODE=mapping_only` (初始保守模式)
4. 重启服务: `pm2 restart woying-backend`
5. 验证: `curl http://127.0.0.1:3000/api/token-monitor/dashboard`
6. 灰度切换: `export KB_RETRIEVAL_MODE=mapping_plus_vector` + 重启
